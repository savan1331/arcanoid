# Арканоид (веб, для iPhone)

Мини-проект: минималистичный арканоид, в который играют в Safari на iPhone
(Макбука нет — поэтому веб). Принцип — минимум затрат, максимум результата.

## Устройство
- Вся игра — один файл `index.html` (чистый JS + canvas, без сборки и npm).
- Настройки (скорость, размеры, шанс бонусов, цвет `HUE`, раскладки уровней
  `LEVELS`) — константы в начале скрипта.
- Хостинг — GitHub Pages: пуш в `main` = обновление игры по ссылке.
- Проверка на компе: открыть `index.html` в браузере в размере телефона
  (мышь двигает ракетку, пробел/клик — запуск, стрелки — тоже ракетка).

## Что уже есть
Ссылка: https://savan1331.github.io/arcanoid/ (репозиторий savan1331/arcanoid).

**v1.** Вертикальный экран, тёмный фон + один акцентный цвет. Очки (10 за удар),
5 уровней по кругу, каждый круг +15% скорости. Кирпичи на 2 удара. Бонусы (15%):
широкая ракетка 10 с, +2 мяча, медленный мяч 10 с, +1 жизнь (максимум — стартовые
+2); повторный бонус продлевает таймер. Сворачивание Safari — пауза.

**v2.** Шестерёнка вверху справа → экран настроек (игра на паузе, после
«Готово» остаётся на паузе). Настройки в localStorage `arkanoid.settings`:
- Режим: «Классика» / «Круг». Круг: квадратные кирпичи 14×14 в центре
  (кружки были — отскоки выходили хаотичными, заменили), ракетка — дуга по
  всему краю круга, мяч улетел за край мимо ракетки — минус жизнь, бонусы
  летят наружу от центра. Фигуры не дальше ~90 от центра, чтобы между ними и
  ракеткой (153) было место — при зазоре 40 мяч возвращался мгновенно.
- Круг — лестница из 10 уровней (`ROUND_LEVELS`: `name` + `parts()` из
  `grid()`/`ring()`), после 10-го по кругу быстрее. Механики: **стены** `W`
  (неразрушаемые, для прохождения не нужны), **ядро** `C` (5 ударов),
  **вращение** (`spin`, рад/с; квадраты едут по орбите, но не поворачиваются;
  наехавший кирпич выталкивает мяч — `pushOut`). Защита от зацикливания: 7
  ударов о стены подряд — угол мяча сбивается на 8–16°. Правило колец: соседи
  не ближе ~20 и кольца не ближе ~20 по радиусу, иначе квадраты наезжают.
  Надписи в круге — под кругом, чтобы видеть фигуру перед запуском.
- Сложность: лёгкая / нормальная / сложная (`DIFF`: скорость, ширина ракетки,
  жизни 5/3/2).
- Управление: «Палец» (свайп в любом месте, ракетка относительно пальца) или
  «Кнопки» (стрелки в нижних углах, мяч — тап по экрану). В круге «вправо» —
  вправо по экрану от места ракетки в момент нажатия (внизу — против часовой,
  вверху — по часовой); пока держите — едет дальше по кругу в ту же сторону.
  Направление НЕ пересчитывается при повторном нажатии в течение 0,6 с и сбоку
  круга (±30°) — иначе ракетку разворачивало обратно (игрок жаловался).
  («Вправо = всегда по часовой» игрок тоже воспринял как баг.)
- Смена режима или сложности начинает новую игру, смена управления — нет.
- Рекорд свой для каждого режима и сложности: `arkanoid.best.<режим>.<сложность>`.

**v3 — игра с другом по сети** (настройки → «Играть с другом»):
- Создатель комнаты (host) получает ссылку `?room=arkanoid-xxxxxx`, кнопка
  «Пригласить» открывает меню «Поделиться». Друг (guest) открывает ссылку —
  игра стартует. Имя спрашивается один раз (`SET.name`), меняется в настройках.
- Как на старых автоматах: у каждого своя партия (кирпичи, уровень, счёт,
  жизни), ходят по очереди — потерял мяч, ход другу. Ходящий шлёт кадры своей
  партии 25 раз/с (`netSnap`, кирпичи — только при изменении), второй смотрит.
  Кончились жизни у одного — второй доигрывает. В конце «Партия окончена»,
  победитель, тап — реванш. Режим и сложность — создателя (у гостя заблокированы).
- Связь: WebRTC через PeerJS (`unpkg.com/peerjs@1.5.4`, грузится только при
  игре с другом), сервер знакомств и посредник — бесплатные публичные PeerJS.
  Обрыв связи — каждый доигрывает один (тост «Связь с другом потеряна»).
- Проверка на компе: две копии игры в одной вкладке (вторая — в iframe со
  `srcdoc` = HTML страницы, команды ей — через `iframe.contentWindow.eval`).
  Вторую вкладку браузерная панель с локальным файлом не открывает.

Нет: звуков, меню, горизонтали, иконки для «На экран Домой».

## Порядок работы
- Сначала короткий план словами (про поведение, не про код) и вопрос
  «делаем так?» — код только после согласия. Упрощения проговаривать отдельно.
- Коммит после каждого законченного шага. **Пуш — только по явному «да»**
  (пуш выкатывает игру по ссылке).
- После каждой фичи обновлять раздел «Что уже есть» в этом файле — это память
  между чатами. Один чат = одна задача.
- Мелкие правки (цвет, размер, текст) — без запуска браузера.
